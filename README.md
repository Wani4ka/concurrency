# Парсер отзывов JetBrains Marketplace

Сервис принимает ссылку на плагин JetBrains Marketplace и ставит задание в очередь. Планировщик раз в секунду передает задания в пул из двух потоков. При сборе сервис загружает первую страницу отзывов через WebClient и разбирает HTML из поля `comment` с помощью Jsoup. По умолчанию отзывы сохраняются во встроенной H2. База создается при запуске приложения.

## Запуск

Для запуска нужен JDK 17. Команды выполняются из корня проекта.

### Windows

```bat
.\gradlew.bat bootRun
```

### macOS и Linux

```sh
sh ./gradlew bootRun
```

Сервер доступен на `http://localhost:8080`. Для загрузки отзывов нужен доступ к `plugins.jetbrains.com`. API-ключ и аккаунт не требуются.

Для хранения в JSON-файлах к команде `bootRun` добавить `--args=--spring.profiles.active=json`. В этом режиме сервис читает и записывает файлы `data/reviews/<pluginId>.json`.

## Проверка

1. Отправить **POST** на `http://localhost:8080/post` с заголовком `Content-Type: application/json`.

   ```json
   {"url":"https://plugins.jetbrains.com/plugin/164-ideavim"}
   ```

   Подходит и ссылка на вкладку [отзывов IdeaVim](https://plugins.jetbrains.com/plugin/164-ideavim/reviews). Когда сервер принимает задание, он возвращает `202 Accepted` и `{"pluginId":164}`.

2. Выполнить **GET**, подставив `pluginId` из ответа на POST. Для IdeaVim адрес будет `http://localhost:8080/answer?pluginId=164`. Если статус `QUEUED` или `RUNNING`, запрос нужно повторить. При `SUCCEEDED` ответ содержит собранные отзывы, при `FAILED` поле `error` содержит причину. Ниже пример успешного ответа с тестовыми данными.

   ```json
   {
     "pluginId": 164,
     "status": "SUCCEEDED",
     "requestedAt": "2026-11-08T12:00:00Z",
     "completedAt": "2026-11-08T12:00:01Z",
     "reviews": [
       {
         "id": 42,
         "text": "Works well & fast.",
         "rating": 4,
         "author": "Demo User",
         "publishedAt": "2026-10-29T18:00:10Z"
       }
     ],
     "error": null
   }
   ```

3. Выполнить `GET http://localhost:8080/answer?pluginId=164&minRating=4&sort=dateDesc`. Ответ содержит отзывы с оценкой 4 или 5, от новых к старым. `minRating` принимает значения от 1 до 5, по умолчанию 1. Для сортировки от старых к новым используется `sort=dateAsc`. По умолчанию действует `dateDesc`. При одинаковой дате отзывы идут по возрастанию ID. Фильтрация и сортировка выполняются через `parallelStream()` после чтения из хранилища. Для недопустимых значений сервер возвращает `400` с причиной в `detail`.

Сервис запрашивает до 20 записей за сбор и сохраняет отзывы, в которых есть текст и оценка от 1 до 5. До первого сбора статус `IDLE`. Повторный POST для плагина со статусом `QUEUED` или `RUNNING` возвращает `202` для уже принятого задания. После завершения новый POST запускает обновление отзывов по ID.

Очередь вмещает 16 ожидающих заданий. Если она заполнена, POST для нового задания вернет `503`. Некорректная ссылка дает `400`. При ошибке Marketplace или таймауте GET показывает `FAILED` с причиной и возвращает ранее загруженные отзывы.

Сервер возвращает ошибки в формате `application/problem+json` и указывает причину в поле `detail`. Ниже приведен ответ на `GET /answer?pluginId=0`.

```json
{
  "title": "Bad Request",
  "status": 400,
  "detail": "pluginId must be positive",
  "instance": "/answer"
}
```

### Проверка после перезапуска

1. После статуса `SUCCEEDED` сохранить массивы `reviews` из ответов GET с фильтром и без него. Проверить, что появился `data/reviews.mv.db` в режиме H2 или `data/reviews/164.json` в режиме JSON. В журнале приложения поток `review-log` пишет о завершении сбора или об ошибке.
2. Перезапустить приложение в том же режиме хранения и выполнить `GET http://localhost:8080/answer?pluginId=164` без повторного POST. Сравнить массив `reviews` целиком с сохраненным до перезапуска. В новом ответе ожидаются статус `IDLE` и `null` в полях `requestedAt` и `completedAt`. Статусы заданий хранятся в памяти.
3. Повторить GET с `minRating=4&sort=dateDesc`. Ожидаются статус `IDLE` и тот же отфильтрованный массив `reviews`.

В профиле `json` доступны ранее собранные отзывы из `data/reviews/`. Данные в каждом режиме хранятся отдельно.

### Bruno

Тот же сценарий можно проверить через готовую коллекцию в [requests](requests).

1. Скачать и установить [Bruno](https://www.usebruno.com/downloads), затем открыть папку `requests` как коллекцию.
2. Выбрать окружение **Local**. В нем уже указан адрес `http://127.0.0.1:8080`. Если приложение запущено на другом порту, нужно обновить `BASE_URL` в окружении.
3. В меню коллекции **...** выбрать **Run**, отметить все запросы, кроме **Get saved reviews**, и нажать **Run Selected Requests**.

После перезапуска отправить отдельно **Get saved reviews**.

Назначение и проверки описаны во вкладке **Docs** каждого запроса в Bruno.
